# NixOS Desktop Configuration

This repository is the complete NixOS configuration for the `nixos`
workstation. It defines a Cinnamon desktop, dual-NVIDIA graphics, local
llama.cpp inference, n8n access through Tailscale Serve, and the system
packages used by the `rileyt` account.

## Repository layout

- `flake.nix` pins NixOS to the `nixos-26.05` branch and exposes the
  `nixosConfigurations.nixos` system.
- `flake.lock` fixes the exact nixpkgs revision used by builds.
- `configuration.nix` contains the desktop, hardware userspace, networking,
  user, package, and service configuration.
- `hardware-configuration.nix` contains generated disk, boot, CPU, and
  machine-detection settings. It is generated by `nixos-generate-config` and
  should not be edited manually.
- `llama-cpp.nix` downloads, verifies, and serves the local GGUF models.
- `n8n.nix` runs n8n locally and exposes it to the tailnet with HTTPS.

## System configuration

The workstation uses:

- systemd-boot on EFI
- hostname `nixos`
- NetworkManager
- timezone `America/Chicago` and locale `en_US.UTF-8`
- Nix flakes and the `nix-command` interface
- unfree packages and redistributable firmware
- the proprietary stable NVIDIA driver with modesetting
- Cinnamon on X11 with LightDM
- PipeWire for ALSA and PulseAudio clients
- KDE Connect and Steam
- Tailscale with manual login and no automatically provisioned auth key
- Docker, enabled at boot with its default local Unix socket

The normal user is `rileyt`, with membership in `wheel`, `networkmanager`,
and `docker`. Docker group membership is effectively root-equivalent and
should only be granted to trusted users.

Cursor, VSCodium, Google Chrome, Git, and Spotify are installed system-wide.
The configuration also creates user-owned Steam and Unsloth data directories
under `/home/rileyt/.local/share`.

The NixOS firewall remains enabled. KDE Connect opens its standard TCP and UDP
ports 1714–1764 for LAN device discovery and pairing. Steam Remote Play,
dedicated-server, and local-network game-transfer firewall rules are not
enabled. Tailscale does not automatically open a public firewall port, and
OpenSSH is not enabled by this configuration.

`system.stateVersion` is `26.05`. Do not change it during a normal NixOS
upgrade; it controls compatibility defaults for stateful services.

## Apply and validate

Run these commands from `/etc/nixos`:

```sh
nix fmt .
nix flake check
nix build .#nixosConfigurations.nixos.config.system.build.toplevel --no-link
pkexec nixos-rebuild switch --flake /etc/nixos#nixos
```

The build command validates the complete system without activating it.
`pkexec` presents the desktop authorization prompt needed to activate the
configuration.

## llama.cpp

`llama-cpp.nix` installs a CUDA-enabled llama.cpp build and defines two
mutually exclusive servers. Both bind only to `127.0.0.1:8080`, use one
request slot, Q8_0 KV caches, Flash Attention, and model layers offloaded to
the NVIDIA GPUs.

Neither server nor model downloader starts automatically at boot. Starting a
server triggers its checksum-verified model download when needed. Starting
one server stops the other because both use the same port and GPUs.

Models are stored in:

```text
/home/rileyt/.local/share/llama.cpp/models
```

### Gemma

- Service: `llama-cpp-gemma4`
- Alias: `gemma-4-12b-it-qat`
- Model: `unsloth/gemma-4-12B-it-qat-GGUF`
- File: `gemma-4-12B-it-qat-UD-Q4_K_XL.gguf`
- Context: 65,536 tokens
- Devices: RTX 3050 and GTX 1660 SUPER

### Qwen 3.5

- Service: `llama-cpp-qwen35`
- Alias: `qwen3.5-2b-mtp`
- Repository: `unsloth/Qwen3.5-2B-MTP-GGUF`
- File: `Qwen3.5-2B-UD-Q8_K_XL.gguf`
- Pinned revision: `e05864f8066d874d5f85aaff007ae57a2a7d1efe`
- SHA-256:
  `1eb01bfc3fbb04323e03fe6123d1d396f531474985b5d06e851ddf0522192f52`
- Context: 34,816 tokens
- Devices: RTX 3050 and GTX 1660 SUPER
- Speculative decoding: embedded MTP head with a draft maximum of six tokens

Qwen uses `--spec-type draft-mtp`; no separate draft model is required.
Parallel slots remain at one because this MTP implementation does not support
multiple slots.

### Switching models

Start Qwen:

```sh
systemctl start llama-cpp-qwen35
```

Start Gemma:

```sh
systemctl start llama-cpp-gemma4
```

Stop whichever model is active:

```sh
systemctl stop llama-cpp-qwen35 llama-cpp-gemma4
```

Inspect the servers and model downloaders:

```sh
systemctl status llama-cpp-qwen35 llama-cpp-gemma4
systemctl status llama-cpp-qwen35-model llama-cpp-gemma4-model
journalctl -u llama-cpp-qwen35 -u llama-cpp-gemma4 --since today
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/v1/models
```

System service control may open a desktop authorization prompt.

### Qwen context benchmark

The benchmark used:

- Intel Core Ultra 7 265K
- 30 GiB usable system memory and 8.8 GiB swap
- RTX 3050 6 GiB
- GTX 1660 SUPER 6 GiB
- llama.cpp build 9190 (`b64739e`)
- Q8_K_XL model weights
- Q8_0 target and MTP draft KV caches
- MTP enabled with `--spec-draft-n-max 6`

Each context candidate used a deterministic, varied synthetic prompt filling
all but 512 tokens of the configured context, followed by a 256-token
generation. The selected limit had to complete prompt processing and
generation without truncation or OOM and reach at least 30 generated tokens
per second in the initial 256-token sample. Testing was capped at one hour.

Key dual-GPU results:

- 32,768 context: 31.01 and 31.46 generated tokens/second on two runs
- 34,816 context: 31.21 generated tokens/second
- 35,840 context: 28.35 generated tokens/second
- 36,864 context: 29.64 generated tokens/second
- 65,536 context: 25.01 generated tokens/second
- 131,072 context: near-full prompt exceeded the 15-minute request timeout

RTX-3050-only prompt processing was much faster, but generation reached only
27.62 tokens/second at 32,768 context. The dual-GPU configuration therefore
provides the highest tested context meeting the 30-token/second target.

The model's native 262,144-token context can be allocated across both GPUs,
but a near-full prompt could not be completed within the benchmark time
budget. It is not treated as a validated usable context on this machine.

MTP acceptance varies with generated content, so 30 tokens/second is a
repeatable benchmark threshold, not a guarantee for every prompt.

## n8n

The locked configuration currently provides n8n 2.34.6. It uses the NixOS
module's dynamic service user, stores state in `/var/lib/n8n`, and uses SQLite;
PostgreSQL is not configured. n8n listens on `127.0.0.1:5678`, with no public
firewall opening.

A oneshot systemd service configures Tailscale Serve to terminate HTTPS and
expose n8n at:

```text
https://nixos.taile9f484.ts.net/
```

Relevant settings declare one trusted reverse-proxy hop, secure cookies, and
the public editor and webhook URLs. n8n and `tailscaled` must both be running
before the Serve rule is installed. The Serve unit is coupled to both
services, so restarting either one reinstalls the HTTPS route automatically.
Stopping the Serve unit removes all Tailscale Serve handlers on HTTPS port
443; this repository assigns that listener only to n8n.

Useful checks:

```sh
systemctl status n8n n8n-tailscale-serve tailscaled
tailscale serve status
curl http://127.0.0.1:5678
```

The hostname identifies the private tailnet endpoint. Do not add plaintext
credentials, API keys, or access tokens to this repository.

## Hardware configuration

`hardware-configuration.nix` records the current root, EFI, and swap UUIDs,
the detected initrd modules, Intel CPU microcode, KVM support, and Intel NPU
support. Re-run `nixos-generate-config` after disk or platform changes and
review the generated diff instead of hand-editing this file.

Because disk UUIDs and the username are machine-specific, review this
repository before publishing it publicly.
